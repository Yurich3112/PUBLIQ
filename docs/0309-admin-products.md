# Administration and products

## Routes and ownership

The localized `/pl/admin/products` and `/en/admin/products` routes list products
from the application database. Add product opens a push aside and changes the
URL to `/admin/products/create` with the selected locale and table query.
Direct entry or reload of that URL renders the same protected list and form.
Breadcrumbs include Products and Add product; browser Back/Forward controls the
URL-addressable panel.

The page, layout and every read/write Server Action enforce `ADMIN_ACCESS`:
a valid Better Auth session and a verified role level of at least 80. The browser
does not supply its author UUID or permission level. See the
[access policy](0203-identity-and-access.md#parameterized-server-access).

| Source under `apps/web/src` | Responsibility |
| --- | --- |
| `app/[locale]/admin/products/page.tsx` | Authorized shell and data-read action |
| `app/[locale]/admin/products/create/page.tsx` | Direct-entry reuse of the protected list page |
| `app/[locale]/admin/products/products-results.tsx` | Query state, table controls and read-error notification |
| `app/[locale]/admin/products/product-create-panel.tsx` | Add link, form, local image preview and URL-driven aside |
| `app/[locale]/admin/products/actions.ts` | Authorized, validated creation boundary |
| `server/products.ts` | Filtered/counting/sorted Prisma read and serializable DTO |
| `server/create-product.ts` | Image normalization, product/file transaction and recovery |
| `schemas/product.ts` | Query/create validation, currency codes and exact price formatting |

## Product model

`Product` maps to SQL table `product` in `packages/database/prisma/schema.prisma`.

| SQL field | Storage | Contract |
| --- | --- | --- |
| `uuid` | UUID primary key | Generated by PostgreSQL `uuidv7()` |
| `code` | Unique varchar(64) | Creation trims and uppercases letters, digits, dot, dash and underscore |
| `name` | varchar(255) | Required, trimmed display name; not unique |
| `description` | Nullable text | Creation accepts up to 10,000 characters; empty becomes null |
| `status` | `ProductStatus` | Defaults to active; creation accepts active/inactive |
| `price` | Decimal(19,4) | Creation accepts an exact nonnegative amount with up to four fractional digits |
| `currency` | varchar(3) | Defaults to PLN; creation validates an uppercase code against runtime-supported currencies |
| `image_file_uuid` | Nullable UUID FK | Logical `File.uuid`, not a public URL or an object-store key |
| `created_at` | timestamptz(3) | Creation timestamp |
| `updated_at` | timestamptz(3) | Updated by Prisma on writes |
| `created_by` / `updated_by` | UUID FKs to User | Derived from the verified server session |
| `last_archived_at` | Nullable timestamptz(3) | Intended last completed archival timestamp; initially null |

Indexes cover audit authors, the image FK and `(status, uuid)`. Image and author
relations restrict deletion. The database does not infer an audit author from
browser input. Amount/code validation belongs to the creation schema; direct SQL
writes must respect the same business rules.

`ProductStatus` contains active, inactive, pending_archiving, archived,
pending_deletion and softdelete. Permanent deletion is an operation, not a stored
product status. Editing and product deletion are implemented and use optimistic
version checks. Permanent product deletion preserves its independently managed
image in the file catalog. Automatic archival and the 30-day trash processor are
deferred in the [backlog](9999-backlog.md).

Migration `20261112090000_products` was generated by Prisma CLI and applied to
the local DEV application database. Other environments require the deliberate
[Prisma deployment workflow](0303-prisma-database.md#prisma-cli-workflow).

## Table and data queries

The authorized page renders the toolbar, headers and paginator without awaiting
the product query. After hydration, a Server Action rechecks access and fetches
data. The body shows the shared four-row loader while the request is pending.
Table query changes update browser history and fetch data without a document
reload. See the [shared table contract](0306-ui-components.md#administration-tables).

Name/code search, lifecycle status and with/without-image filters apply before
database pagination. Sort columns are code, name, status, price, currency and
updated time, with a stable UUID tie-breaker. Count and page data are read through
a Prisma transaction. Prices sort numerically in SQL; amounts in different
currencies are not converted to a common currency.

Amounts cross the server/client boundary as decimal strings. Formatting retains
all four fractional digits when needed and avoids converting the whole amount
to a JavaScript float. A row without an image displays Without image; a linked
row displays its file name. Checkbox selections currently have no bulk consumer.
Info opens audit fields and identifiers in a push aside.

An empty catalog displays No data. Initial failure displays a red full-width
ERROR row and a notification in the shared strip; headers and paginator remain.
Unavailable totals use dashes and disabled pagination. Failed refresh can retain
the last page with an error row. A denied refresh clears the protected results.

## Create with an optional image

The form requires code, name, price and currency, and offers description,
active/inactive status and an optional image. Price accepts a comma or dot decimal
separator. Field validation runs in the browser and again on the server. A duplicate
code remains a recoverable form error. The selected image can be removed before
saving; local Blob preview URLs are revoked when replaced or unmounted.

The server accepts a nonempty static JPEG, PNG or WebP of up to 8 MiB. It checks
the real byte signature and decodes with Sharp, limits input to 16 million pixels,
rejects unsupported/animated content, rotates, strips metadata and encodes WebP
inside 1600 × 1600 without enlargement. The filename derives from the product
code. Client MIME/extension checks alone do not authorize the upload.

Without an image, creation writes only Product. With an image, it creates File,
revision 1 and Product in one PostgreSQL transaction, writes the normalized object
before commit, and links Product to the logical file. Upload recovery first checks
whether the product committed; it never blindly deletes a committed image after
an ambiguous response. An uncommitted attempted object is removed where recovery
can confirm that cleanup is safe. Database and storage remain separate services.

Pending save disables the form and aside dismissal. Success reports through the
notification strip, closes to the list URL and refreshes data. Failure leaves the
form available for retry. A linked image blocks physical file deletion until
products release it; see [file deletion](0307-admin-files.md#permanent-deletion).

Stored-image delivery uses an administrator-authorized endpoint, resolves the
latest file revision and normalizes supported image formats to private WebP.
PDF and other unsupported formats return 415 with a download hint in the UI.
Image edits and catalog previews use this protected endpoint; local unsaved
uploads use a browser-only preview.

## Verification and limits

```powershell
pnpm test:web
pnpm typecheck
pnpm lint
pnpm test:products:integration
pnpm test:database:integration
pnpm test:auth:integration
```

The integration commands require the matching local PostgreSQL container and
disposable-database privileges. They create and remove their own fixtures.
The product database integration checks the schema/FKs/locking; creation tests
also cover normalization and recovery with controlled storage failures.

Recorded checks passed 107 Web tests, Web/package type checks, ESLint and 18
tooling tests, plus disposable database/seed and Better Auth/OIDC regressions.
An isolated Edge profile with a disposable live Keycloak account verified both
creation variants, exact price, direct create URL, 320px layout, four-row/100ms
loading, query changes without document navigation and denial of the next data
action after changing ADMIN to USER. Its account, products and images were removed.

That browser check began OIDC through the sign-in/social endpoint. Intermittent
502s while starting login through a Server Action remain unclassified; this does
not establish every login-start path. The helper under ignored `.local/ui-check/`
is not a committed CI browser suite. A production build was not repeated over
the active dev `.next`; QA/PROD delivery and broad accessibility acceptance remain
separate work.
